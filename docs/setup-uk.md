# Що підключити і як

Покрокова інструкція для запуску GoMammy та відстеження результатів.
Порядок має значення: без домену немає ні аналітики, ні індексації.

---

## Крок 1. Домен і хостинг (30 хв)

Сайт — це Next.js, найпростіше на Vercel (безкоштовного плану вистачить надовго).

1. Залийте репозиторій на GitHub.
2. vercel.com → **Add New → Project** → імпортуйте репозиторій. Vercel сам
   визначить Next.js, нічого налаштовувати не треба.
3. **Settings → Domains** → додайте свій домен, Vercel покаже, які DNS-записи
   прописати в реєстратора.
4. **Settings → Environment Variables** → додайте для оточення *Production*:

   | Змінна | Значення |
   | --- | --- |
   | `NEXT_PUBLIC_SITE_URL` | `https://вашдомен.com` (без слеша в кінці) |
   | `NEXT_PUBLIC_GA_ID` | поки порожньо, заповните на кроці 2 |

5. Redeploy.

> **Важливо.** `NEXT_PUBLIC_SITE_URL` — це те, з чого будуються canonical,
> hreflang, sitemap і OG-зображення. Якщо його не задати, всюди буде
> `gomammy.com` із коду. Прев'ю-деплої автоматично закриті від індексації —
> у Google потрапить лише продакшн.

## Крок 2. Google Analytics 4 (20 хв)

### 2.1. Створити ресурс

1. analytics.google.com → **Admin → Create → Property**.
2. Назва `GoMammy`, часовий пояс і валюта — ваші.
3. **Data streams → Add stream → Web**, URL вашого домену, назва `Website`.
4. Скопіюйте **Measurement ID** — це `G-XXXXXXXXXX`.
5. Vercel → Environment Variables → `NEXT_PUBLIC_GA_ID` = `G-XXXXXXXXXX` → Redeploy.

### 2.2. Перевірити, що працює

1. Відкрийте сайт, у банері cookie натисніть **Прийняти все**.
2. GA4 → **Admin → DebugView** (або **Reports → Realtime**) — маєте побачити себе.

> До згоди на cookie GA не завантажується взагалі — жодного запиту до Google.
> Це навмисно, вимога GDPR. Тому в Realtime ви себе не побачите, доки не
> натиснете «Прийняти».

### 2.3. Позначити ключові події

GA4 → **Admin → Events**. Через 24 години там з'являться наші події. Позначте
перемикачем **Mark as key event**:

- `app_store_click`
- `google_play_click`
- `app_cta_click`

Тоді в звітах буде видно конверсію «стаття → застосунок».

Повний список подій, які шле сайт:

| Подія | Коли спрацьовує |
| --- | --- |
| `article_view` | відкрито статтю |
| `week_view` | відкрито сторінку тижня |
| `article_scroll_50` / `article_scroll_90` | дочитано до половини / до кінця |
| `app_cta_view` | промо-блок застосунку потрапив в екран |
| `app_cta_click` | клік по промо-блоку |
| `app_store_click` / `google_play_click` | клік по кнопці стора |
| `site_search` | пошук по сайту |
| `language_switch` | зміна мови |
| `toc_click` | клік у змісті статті |

У кожної події є параметри `article_id`, `week`, `cta_location`, `language` —
за ними видно, **яка саме сторінка** привела до кліку.

### 2.4. Звіт «яка стаття веде в стор»

GA4 → **Explore → Free form**:
- Rows: `Page path`
- Values: `Views`, `app_cta_view`, `app_store_click`, `google_play_click`

Це і є воронка з ТЗ: 10 000 переглядів → 3 200 показів CTA → 420 кліків.

## Крок 3. Google Search Console (15 хв)

Це головний інструмент, щоб побачити, «як воно йде» в пошуку.

1. search.google.com/search-console → **Add property → Domain** (варіант із
   доменом краще: покриває всі мови й піддомени одразу).
2. Google дасть TXT-запис — додайте його в DNS реєстратора, натисніть Verify.
3. **Sitemaps** → додайте `sitemap.xml` → Submit.
   Там 390 сторінок з усіма мовними версіями.
4. **URL Inspection** → вставте `https://вашдомен.com/uk` → **Request indexing**.
   Так само для 2–3 ключових сторінок. Решту Google знайде сам через sitemap.

### Що дивитись і коли

| Коли | Де | Що має бути |
| --- | --- | --- |
| через 2–3 дні | **Pages** | сторінки переходять у «Indexed» |
| через 3–7 днів | **Performance** | перші покази (impressions) |
| через 2–4 тижні | **Performance → Queries** | за якими запитами вас знаходять |
| постійно | **Pages → Why pages aren't indexed** | причини, чому щось не в індексі |

У **Performance** увімкніть фільтр **Country** і **Search appearance** — так
побачите, яка мовна версія працює краще.

> Індексація 400+ сторінок займає тижні, іноді місяці. Це нормально. Спочатку
> Google візьме головну та категорії, потім поступово сторінки тижнів.

### Зв'язати з GA4

GA4 → **Admin → Product links → Search Console links** → підключіть.
Тоді запити з пошуку будуть видні прямо в GA4.

## Крок 5. Атрибуція встановлень застосунку

Сайт уже додає до кожного посилання на стор параметри — але **стори читають
різні параметри**, і це найчастіша причина, чому «встановлення взялися нізвідки».

### Google Play

Посилання виглядає так:

```
…/details?id=com.bubbi.app&utm_source=website&utm_medium=article&utm_campaign=bubbi&utm_content=week_20
```

Play Console → **User acquisition → Acquisition reports** → фільтр по
`utm_source = website`. У розрізі `utm_content` буде видно, з якої саме
сторінки прийшли встановлення.

### App Store

Apple **ігнорує** `utm_*`. Тому для iOS сайт додає власний параметр Apple:

```
https://apps.apple.com/app/id6782431465?ct=week_20&mt=8
```

App Store Connect → **App Analytics → Acquisition → Campaigns** → там
з'явиться `week_20`, `article_hospital-bag-checklist` тощо.

Якщо у вашому акаунті використовується **provider token**, додайте змінну
`NEXT_PUBLIC_APPLE_PROVIDER_TOKEN` на Vercel — він автоматично піде в
параметр `pt`.

> Значення `ct` обмежене 40 символами — сайт обрізає довші автоматично.

## Крок 6. CMS (коли з'явиться потреба)

Поки весь контент — типізовані файли в репозиторії, редагувати може розробник.
Щоб контент-менеджер працював сам:

1. sanity.io → створіть проєкт, скопіюйте **Project ID**.
2. Vercel → змінні: `NEXT_PUBLIC_SANITY_PROJECT_ID`, `NEXT_PUBLIC_SANITY_DATASET=production`.
3. Redeploy → студія відкриється на `вашдомен.com/studio`.
4. Sanity → **API → Webhooks** → додайте Vercel Deploy Hook, щоб публікація
   в CMS автоматично пересобирала сайт.

## Що зробити **до** того, як просити індексацію

Це не технічні задачі, але вони впливають на довіру й на те, як Google оцінює
медичний контент (E-E-A-T):

- [ ] **Автори й медичні рецензенти.** Зараз це знеособлені заглушки
      («Редакція GoMammy»). Для контенту про здоров'я потрібні реальні люди
      з іменами й кваліфікацією.
- [ ] **Юридичні сторінки.** Написані лише англійською; інші мови показують
      повідомлення й закриті від індексації. Політику конфіденційності треба
      перекласти з юристом, а не машинно.
- [ ] **Зображення статей і категорій** — зараз це згенеровані SVG-заглушки.
      Скриншоти застосунку вже реальні, взяті зі сторінки App Store.
- [ ] **Кнопки сторів** — замінити на офіційні бейджі Apple / Google
      (вимога їхніх брендбуків).

## Коротко: мінімум, щоб «подивитися, як воно йде»

1. Задеплоїти на Vercel + свій домен, задати `NEXT_PUBLIC_SITE_URL`.
2. Створити GA4, вставити `NEXT_PUBLIC_GA_ID`, прийняти cookie, перевірити Realtime.
3. Підтвердити домен у Search Console, віддати `sitemap.xml`.
4. Через тиждень зайти в Search Console → Performance.

Перші три кроки — приблизно година роботи.
